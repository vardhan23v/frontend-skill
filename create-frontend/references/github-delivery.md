# GitHub delivery

Companion to steps 1, 10 and 12 of `SKILL.md`. Read it when the user asks to commit, push, open a pull request, add CI, deploy from GitHub, or when the project already has a GitHub remote.

Delivery is part of the work, not an afterthought. A frontend is finished when the branch is reviewable, CI is honest, and the deployed URL has been checked — or when the report says exactly which of those did not happen.

## The identity rule

The commit author and committer are the person whose repository it is. Never a bot, never an agent, never a shared service account.

1. Read the identity before doing anything:
   ```bash
   git config --get user.name
   git config --get user.email
   gh auth status
   gh api user --jq .login
   ```
2. If the name or email is missing, ask. Do not invent one and do not copy one from another repository.
3. Set it for this repository only, never globally:
   ```bash
   git config --local user.name "Full Name"
   git config --local user.email "you@example.com"
   ```
4. Never add `Co-Authored-By:` trailers for an agent or bot. Never add a "generated by" footer. If an earlier commit already has one, do not rewrite history without explicit permission; say what you found.
5. CI workflows run checks; they do not author commits. If a workflow must commit (for example a visual-baseline update), it asks first and uses the repository owner's configured identity, not `github-actions[bot]`.
6. Never force-push a shared branch. `--force-with-lease` only on your own feature branch, and only after saying why.
7. Do not merge, tag or deploy unless the user asked. Opening the pull request is the default finish line.

Check the commits you are about to push:

```bash
git log --format='%h %an <%ae>%n%b' origin/main..HEAD
```

The output must show the user's name and email, and no bot trailer.

## Preflight

```bash
git status --short
git branch --show-current
git remote -v
git fetch origin
git log --oneline --decorate -5 origin/main
gh auth status
gh repo view --json nameWithOwner,defaultBranchRef
```

Stop and ask when:

- the working tree has changes the user did not ask you to include;
- the remote is not the repository the user named;
- `gh` is not installed or not authenticated (use `git` and a pull-request URL instead, or ask);
- the default branch is protected and the user asked for a direct push;
- the branch has diverged and a merge or rebase would be destructive.

Never install or authenticate `gh` silently. Never use a token that is not the user's.

## Branch and commit

Use a short, typed branch name:

```bash
git switch -c feat/<slug> origin/main
```

| Change | Prefix |
|---|---|
| New feature or page | `feat/` |
| Bug fix | `fix/` |
| Refactor with no behaviour change | `refactor/` |
| Tests, CI or tooling | `chore/` |
| Documentation | `docs/` |

Stage only the files you changed. Do not commit `.env*`, secrets, build output, dependency folders, screenshots the user did not ask for, or unrelated formatting.

```bash
git add path/to/file another/path
git diff --cached --stat
git diff --cached
git diff --check
```

Commit messages are imperative and explain why:

```text
feat: add the students list page

Reads /api/students through the existing typed client, adds loading,
empty and error states, and covers the page with a Playwright smoke test.

Verified: lint, typecheck, unit tests, build, browser at 375 and 1280.
```

Rules:

- subject at most 72 characters, no trailing period;
- one logical change per commit; do not mix a refactor with a feature;
- no `[skip ci]` unless the user asked;
- no secrets in the message or the diff;
- check the author again before committing.

## Open the pull request

Write the body to a file so newlines and markdown survive:

```bash
cat > /tmp/pr-body.md <<'EOF'
## Summary
- ...

## Verification
- Code:
- Types:
- Build:
- Tests:
- Browser:
- Visual:
- Accessibility:
- Delivery:

## Screenshots
- Desktop 1280:
- Mobile 375:

## Backend and environment
- Backend dependencies:
- Environment variables:

## Risks and rollback
- ...
EOF

gh pr create --base main --head feat/<slug> \
  --title "feat: ..." \
  --body-file /tmp/pr-body.md
```

Use the repository's own PR template if one exists. Link the issue when there is one. Do not fill the verification section with claims that were not run; write `not run` and the command.

## Watch CI

```bash
gh pr checks --watch
gh run list --branch feat/<slug> --limit 5
gh run view <run-id> --log-failed
```

- A green check means the workflow actually ran and passed. If no workflow exists, say "no CI configured", not "CI passed".
- When a job fails, read the failed log, fix the cause, and push a new commit. Do not retry the same command unchanged more than twice.
- Do not disable a check, add `continue-on-error`, or weaken an assertion to get green.
- If CI is flaky for infrastructure reasons, say so and rerun once; do not hide it.

## GitHub Pages

Pages hosts static output only. Use it for plain HTML, Vite, Astro static, or a Next.js static export — not Next.js SSR, API routes or server actions.

1. Copy [`assets/github/pages.yml`](../assets/github/pages.yml) to `.github/workflows/pages.yml` and set the build output path (`dist`, `out`, or the project root).
2. For a project page at `https://<user>.github.io/<repo>/`, set the framework base path as well as the asset paths:
   - Vite: `base: '/<repo>/'` in `vite.config.*`
   - Astro: `base: '/<repo>/'`
   - Next.js static export: `basePath: '/<repo>'` and `assetPrefix: '/<repo>/'`
   - Plain HTML: make internal links relative or prefix them
   A custom domain served from the site root uses `/`, not the repository name.
3. Client-side routing needs a fallback. The workflow copies `dist/index.html` to `dist/404.html`; GitHub Pages serves that for unknown paths and the router takes over. A server-rendered host is better when deep links matter.
4. In the repository: **Settings → Pages → Source: GitHub Actions**. Confirm the environment is `github-pages`.
5. Open the deployed URL, a deep link, and a missing path. Check the console, the network panel and the base-path assets. A page that only works at `/` is not deployed.
6. GitHub Pages cannot set custom response headers. Do not claim CSP or HSTS for a Pages site; put a CDN or proxy in front, or state the limitation (see `security-headers.md`).

## Releases and tags

Only when asked:

```bash
git tag -a v4.0.0 -m "v4.0.0"
git push origin v4.0.0
gh release create v4.0.0 --generate-notes
```

The tag must match the project or skill version. Release notes list user-visible changes, breaking changes, migrations and known limitations. Never move or delete a published tag.

## What goes in the report

Add to the verification report:

```text
GIT
- Branch:
- Commit:
- PR:
- CI: (workflow name and result, or "not configured")
- Preview:
- Deployed:

DELIVERY
- Security headers:
- Analytics and consent:
- Error reporting:
```

If a line was not checked, say `not run` and the command. Never imply a pull request, CI run or deployment that does not exist.

## Failure table

| Symptom | Likely cause | What to do |
|---|---|---|
| `gh: not logged in` | No GitHub CLI session | Ask the user to run `gh auth login`, or use `git` and the web PR URL. Never use another account. |
| Push rejected: protected branch | Direct push to `main` | Push the feature branch and open a PR. Do not disable protection. |
| Push rejected: non-fast-forward | Remote moved | `git fetch`, rebase your branch on `origin/main`, resolve, re-run checks. No force-push to shared branches. |
| CI fails only on a clean install | Lockfile not committed, missing peer dependency, or Node version mismatch | Reproduce with `npm ci` and the CI Node version; commit the lockfile; fix the dependency. |
| CI cannot find a script | The project uses a different script name | Run the real script; update the workflow, do not add a no-op. |
| Pages shows 404 for deep links | No SPA fallback | Copy `index.html` to `404.html`, or use a host with rewrites. |
| Pages loads without CSS or JS | Wrong base path | Set the framework base path and rebuild. |
| Pages workflow cannot deploy | Pages source is not "GitHub Actions" or permissions are missing | Fix the repository setting and the `pages: write` / `id-token: write` permissions. |
| CSP blocks a script, font or image | The origin is not allowlisted | Add the exact origin; do not add `*` or `unsafe-eval`. |
| Analytics sends before consent | The tag loads before the consent decision | Load analytics only after consent; default to denied. |
| Visual test fails on every run | Fonts, animations or device scale differ | Stabilise the fixture (wait for fonts, disable motion), then update the baseline deliberately. |
